# qa-pilot 0.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two QA scenarios (`task-qa`, `project-audit`), spec-audit phase 1 (entity cards, buckets, suppressed list, actions.json, score.py), and a corrected, extended knowledge base.

**Architecture:**
- **Skills** are Markdown instruction files (`skills/<name>/SKILL.md`) plus shared references.
- **Python helpers** live under `scripts/kb` and `skills/spec-audit/scripts`; they are stdlib-only and tested with unittest/pytest.
- **Knowledge** is stored as JSON rule records, validated and rendered by `scripts/kb/render_rules.py`.
- **Web patterns** are rule records with an extra `pattern` object, rendered into `references/web-patterns.md`.

**Tech Stack:** Python 3 stdlib, Markdown, JSON, `jq` for ad-hoc checks.

**Spec:** `docs/superpowers/specs/2026-10-19-qa-pilot-0.5-design.md` (incl. §8 builder-check answers).

## Global Constraints
- Branch `feat/book-knowledge-base`. Commits stay local; never push.
- Rules are written in Russian and paraphrased. No copyrighted text beyond ≤2-sentence quotes. CC BY-SA/CC BY sources carry attribution in `source.origin` (URL + section).
- Non-book ids: `QAP-<TOPIC>-NNN`. `source.origin` is required.
- New KB domains stay in `knowledge/qa-pilot/drafts/` (not loaded by `rules_pack.py`) until after the pilot-project eval (Task 5). Then they move to `knowledge/qa-pilot/rules/`.
- Caps:

  | Domain | Max rules |
  |---|---|
  | security | ≤40 |
  | test-code | ≤35 |
  | api-http | ≤25 |
  | test-strategy | ≤25 |
  | auth | ≤15 |
  | ai-systems | ≤15 |
  | web-patterns | ~18 (10 `must-check`) |
  | web-invariants | 6 |

- Buckets:
  - **Must** = P1 | BUG | P2 on a confirmed critical flow. Uncapped, with a warning above 10.
  - **Should** = other P2, ≤8.
  - **Highlight** = P3, one line each.
  - Suppressed items are outside the action list.
- `task-qa` targets: plan ≤80k tokens, verify ≤100k tokens. Auto tests: ≤5 per task, ≤1 new e2e, and only with a sourced expected result. A BUG test must fail before the fix. BUG fixes need the owner.
- Gates: `python3 -m unittest discover -s scripts/kb`, `(cd skills/spec-audit/scripts && python3 -m unittest -q)`, `python3 scripts/kb/render_rules.py knowledge/catalog --check` and `python3 scripts/kb/render_rules.py knowledge/qa-pilot --check` are all green before every commit.
- Every subagent appends progress to a scratch file in the session scratchpad.

## Review Focus
1. A rule file with an unknown `authority` value, or `pattern` on a non-WEB rule → the validator rejects it with a clear message (Task 1 tests).
2. An `-actions.json` with an item missing `bucket`, or a Should count above 8 → `score.py` reports a schema error and does not crash (Task 4 tests).
3. Unclassified book rules keep their severity in packs; only classified `author-opinion`/`vendor-guideline` `must` rules are shown as `should` (Task 1 tests).
4. A draft domain must not leak into packs before it is promoted (Task 1 test: `drafts/` is ignored).
5. `--agreement` with runs that have different cell sets → agreement is computed over the union, and the missing cells count as disagreement (Task 4 tests).

### Task 4: `-actions.json` schema + `score.py`

**Files:**
- Create: `skills/spec-audit/scripts/score.py`, `skills/spec-audit/scripts/test_score.py`.
- Create: `references/actions-schema.md`.
- Create: `docs/superpowers/notes/evals/pilot-rubric.json` (G1–G21 from the rubric note: `id`, `text`, `expect`: pass condition text).

**Interfaces:**
- **`-actions.json`:**

  ```json
  {"feature": "...", "depth": "...",
   "actions": [{"id", "bucket": "must|should|highlight", "kind": "bug|test|question", "title", "expected", "source", "level", "target", "pattern"}],
   "suppressed": [{"title", "pattern", "filter"}],
   "cells": [{"entity", "pattern", "verdict"}]}
  ```

- **`mapping.json`** (written by the judge): `{"G1": {"verdict": "pass|partial|fail", "actions": [ids], "note": str}}`.
- **CLI:**
  - `score.py score --actions A --mapping M --rubric R` → JSON `{pass, partial, fail, buckets{must,should,highlight}, questions, question_share, warnings[]}`;
  - `score.py agreement A1 A2` → `{cells_union, agree, ratio}`;
  - `score.py validate A` → exit 1 with errors.

- [ ] Step 1: Tests:
  - `test_validate_missing_bucket`;
  - `test_should_cap_warning` (9 Should → warning `should>8`);
  - `test_must_warning_over_10`;
  - `test_score_counts`;
  - `test_agreement_union` (`{a:OK,b:GAP}` vs `{a:OK,c:OK}` → union 3, agree 1, ratio 0.333).
- [ ] Step 2: Run the tests and expect FAIL. Implement, then expect PASS. Run the gates.
- [ ] Step 3: Commit `feat(spec-audit): actions.json schema + score.py`.
