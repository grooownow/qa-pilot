# qa-pilot 0.9.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add harness scan, fit estimate, budget mode, strategy check, e2e skeleton, UI-testing strategy and a UI test audit to qa-pilot.

**Architecture:** Instructions-first: new references (`budget.md`, `ui-testing.md`), new rules file `ui-testing.json`, edits to onboard / write-tests / audits / task-qa, one new internal skill `ui-test-audit` with one stdlib script `ui_inventory.py`. `profile_drift.py` learns the `## Harness` section. Recommendations live in a new user-project file `docs/qa/strategy-check.md`; the profile stays facts only.

**Tech Stack:** Markdown skills, Python 3 stdlib scripts with `unittest`.

**Spec:** `docs/superpowers/specs/2026-10-27-qa-pilot-0.9-strategy-ui-design.md`

## Global Constraints

- Branch `feat/0.9.0`. Never push, merge or tag inside a task.
- Gates that must stay green after every task: `python3 -m unittest discover -s <dir>` for `scripts/kb`, `scripts/plugin`, `skills/spec-audit/scripts`, `skills/onboard/scripts`, `skills/test-code-audit/scripts` (and `skills/ui-test-audit/scripts` from Task 6); `python3 scripts/plugin/check_skills.py`; `python3 scripts/kb/render_rules.py --check knowledge/catalog` and `knowledge/qa-pilot`; `claude plugin validate .`.
- Skill descriptions ≤ 1024 chars and contain "Not for … (use qa-pilot:<skill>)".
- Scripts: stdlib only, unit-tested; exit 0 ok / 2 bad input.
- `standard` budget mode = today's behaviour, unchanged.
- Installing tools: only after an explicit yes to the exact list (packages with versions, commands, files to change); a yes covers that list only; never global installs; never touch CI.
- The profile (`docs/qa/project-profile.md`) holds facts only; recommendations go to `docs/qa/strategy-check.md`, rewritten whole on each run, with its own `Generated by qa-pilot on <date>` line.
- Copy tone: mechanism, no hype. Never name the author of the book catalog.
- Rule files are edited as JSON and re-rendered with `python3 scripts/kb/render_rules.py knowledge/qa-pilot`; never edit the rendered `.md` by hand.

## Review Focus

1. A profile written before 0.9 (no `## Budget`, no `## Harness`) → every skill runs as `standard`; drift reports nothing new. Pinned in Task 2 (drift test) and Task 1 (budget text).
2. `## Harness` with `manually` and no code spans, or a row whose path is a directory → no false `missing-path`; a deleted workflow file → `missing-path`. Task 2 tests.
3. A component library with cyclic imports or a barrel `index.ts` re-exporting atoms → `ui_inventory.py` terminates and classifies through the barrel. Task 6 tests.
4. A project with no UI library → onboard writes "no UI library found", `ui-test-audit` says so and stops without writing a report. Task 5 and Task 7 text.
5. The owner says yes to an install list and the agent later needs one more package → it asks again. Task 4 text, Task 7 text.

### Task 6: `ui_inventory.py`

**Files:**
- Create: `skills/ui-test-audit/scripts/ui_inventory.py`, `skills/ui-test-audit/scripts/test_ui_inventory.py`

**Interfaces:**
- CLI: `python3 ui_inventory.py --root <dir> --lib <path> [--lib <path> ...] [--alias <prefix>=<path> ...] [--json]`. Exit 2 when a `--lib` path does not exist or none given.
- `inventory(root: Path, libs: list[Path], aliases: dict[str, Path]) -> dict` returning `{"components": [{"name", "path", "kind": "atom"|"composition", "uses": [names], "stories": [story export names], "play_stories": [names], "tests": [paths]}], "unresolved": [{"file", "import"}], "summary": {"components", "atoms", "compositions", "with_stories", "with_play"}}`; components sorted by path.
- Component files: `*.tsx|*.jsx|*.vue|*.svelte` under the libs, excluding `*.stories.*`, `*.test.*`, `*.spec.*`, `*.d.ts`; name = file stem, or the parent dir name when the stem is `index`. Pure barrels (`index.ts`/`index.tsx` with only re-exports) are not components but are followed when resolving imports.
- Imports: `from '<spec>'` / `import '<spec>'`. Relative and alias specs resolve to files (try extensions and `/index.*`); a resolved library component → `uses`; a resolved barrel → the imported names `{ A, B }` that are components. Package imports are ignored. An alias-looking spec (starts with `@/` or `~/` or a given alias prefix) that does not resolve → `unresolved`. A component never `uses` itself; cycles do not loop.
- Stories: `X.stories.(tsx|jsx|ts|js)` maps to component `X`; story names = `export const <Name>`; `play_stories` = exports whose object literal contains `play` (regex `play\s*[:(]` between this export and the next). Tests: `X.test.*` / `X.spec.*` next to or under the libs map to `X`.

- [ ] **Step 1: Failing tests** (`unittest`, temp dirs), names and assertions:
  - `test_atom_and_composition`: `Button.tsx` (no lib imports), `Dialog.tsx` imports `./Button` → Button atom, Dialog composition with `uses == ["Button"]`.
  - `test_barrel_resolution`: `index.ts` re-exports Button and Input; `Form.tsx` does `import { Button, Input } from "./"` → Form uses `["Button", "Input"]`; `index` not listed as a component.
  - `test_alias_and_unresolved`: `--alias @/ui=src/ui`; `Card.tsx` imports `@/ui/Button` → uses Button; `import x from "@/lib/missing"` → one `unresolved` entry; `import React from "react"` ignored.
  - `test_cycle_terminates`: A imports B, B imports A → both composition, no exception.
  - `test_stories_and_play`: `Button.stories.tsx` with `export const Primary = {}` and `export const Clicked = { play: async () => {} }` → stories `["Primary","Clicked"]`, play_stories `["Clicked"]`; stories file not a component.
  - `test_index_dir_naming`: `Select/index.tsx` → component name `Select`.
  - `test_cli_bad_lib_exits_2`: missing `--lib` path → exit 2.
